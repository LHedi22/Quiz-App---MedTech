Added `app/ml/omr/align.py::align_page(image, template, dpi) -> AlignmentResult`: detects the 4 fiducials via OpenCV contour/shape filtering (rotation-invariant `minAreaRect`-based extent/aspect checks, not axis-aligned-bbox ones, which would falsely reject a rotated square), computes a homography via `cv2.getPerspectiveTransform`, and warps the scan back to canonical page geometry. Discovery/design decision: the fiducial size (22pt) was deliberately chosen well above this project's QR finder-pattern outer-square size (~17pt, computed from the actual `qrcode` module count at ERROR_CORRECT_M for a UUID-length `qr_id`) — a naive detector otherwise confuses the two, since a QR finder pattern's outer ring is geometrically a solid square to `cv2.findContours`. Also discovered and fixed a real correspondence-ambiguity bug: a rectangle is symmetric under 180-degree rotation, so a candidate-to-corner assignment that just minimizes similarity-transform residual is a coin flip between the true match and its 180-degree-flipped twin (both fit near-perfectly) — fixed by breaking ties among near-equal-residual assignments in favor of the smallest absolute recovered rotation angle, since a real scan is never rotated anywhere near 180 degrees.
