[Phase 5.1] Added a `fiducials` block to `app/config/pdf_template.json` (4 solid black 22pt corner squares, 12pt margin from each edge) and `_draw_fiducials` in `pdf_gen.py` to render them as vector rects (not raster images, so Phase 4's "QR is the only embedded raster image on the page" test assertions still hold unmodified) on every page. Factored the bubble-center and new fiducial-position math out of `pdf_gen.py` into `app/services/geometry.py` (`bubble_center_pt`, `fiducial_positions_pt`/`fiducial_centers_pt`, `pdf_point_to_pixel`, `qr_box_pixel_rect`) so PDF rendering and OMR alignment share one coordinate source of truth instead of drifting. Added `app/ml/omr/align.py::align_page(image, template, dpi) -> AlignmentResult`: detects the 4 fiducials via OpenCV contour/shape filtering (rotation-invariant `minAreaRect`-based extent/aspect checks, not axis-aligned-bbox ones, which would falsely reject a rotated square), computes a homography via `cv2.getPerspectiveTransform`, and warps the scan back to canonical page geometry. Discovery/design decision: the fiducial size (22pt) was deliberately chosen well above this project's QR finder-pattern outer-square size (~17pt, computed from the actual `qrcode` module count at ERROR_CORRECT_M for a UUID-length `qr_id`) — a naive detector otherwise confuses the two, since a QR finder pattern's outer ring is geometrically a solid square to `cv2.findContours`. Also discovered and fixed a real correspondence-ambiguity bug: a rectangle is symmetric under 180-degree rotation, so a candidate-to-corner assignment that just minimizes similarity-transform residual is a coin flip between the true match and its 180-degree-flipped twin (both fit near-perfectly) — fixed by breaking ties among near-equal-residual assignments in favor of the smallest absolute recovered rotation angle, since a real scan is never rotated anywhere near 180 degrees. Verified in `backend/tests/test_align.py` (6 tests) using synthetically rotated (5°/15°/30°, `cv2.warpAffine` with expanded white-padded canvas) renders of a real generated version PDF (rasterized via PyMuPDF, no fixture image files needed): recovered bubble-center pixel coordinates are within a defined ±3px tolerance at all three angles (actual observed error ~0.8px, well inside tolerance) against a forward-computed ground truth (the known rotation matrix applied to the template's true bubble coordinates — not circular, since only the 4 fiducial corners feed the homography fit); a dedicated occlusion test whites out one corner's fiducial region and asserts `AlignmentResult(success=False, error=...)` with no exception and no warped image, plus a companion test with all 4 fiducials removed. Full backend suite (32 passed, 32 skipped needing local Supabase) still green, `ruff`/`black --check` clean. New dependencies added to `pyproject.toml`: `opencv-python-headless`, `scikit-learn`, `numpy`, `joblib` (installed into `backend/.venv`, the project's actual venv — the system `python` on this machine is a different, unrelated interpreter without the project's packages, noted here since it tripped up test discovery once). — DoD verified.
