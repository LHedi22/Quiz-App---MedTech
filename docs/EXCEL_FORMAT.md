# Excel upload format

Professors upload a single `.xlsx` file per quiz. The first worksheet is read; the
first row is a header row and is skipped. Every row after that is one MCQ question.

## Columns

| Column         | Required | Type   | Notes                                                        |
|----------------|----------|--------|---------------------------------------------------------------|
| `question_text`| yes      | text   | The question prompt. Must be non-empty.                       |
| `option_a`     | yes      | text   | Text for option A. Must be non-empty.                         |
| `option_b`     | yes      | text   | Text for option B. Must be non-empty.                         |
| `option_c`     | yes      | text   | Text for option C. Must be non-empty.                         |
| `option_d`     | yes      | text   | Text for option D. Must be non-empty.                         |
| `correct_option`| yes     | text   | Exactly one of `A`, `B`, `C`, or `D` (case-insensitive).       |

Column order matters and must match exactly; column names in the header row are not
parsed, only position. Rows are read in top-to-bottom order and become each question's
`order_index` (1-based), matching the `questions` table's canonical Excel order.

## Validation rules

Applied per row, independently — a file can have multiple invalid rows and every one
of them is reported together, not just the first:

1. `question_text` must be non-empty (after trimming whitespace).
2. `option_a` through `option_d` must each be non-empty (after trimming whitespace).
3. `option_a` through `option_d` must be pairwise distinct within the row (no duplicate
   option text, e.g. `option_a` and `option_c` cannot both be `"Paris"`).
4. `correct_option` must be exactly one of `A`, `B`, `C`, `D` (case-insensitive; stored
   uppercase). Empty, missing, or any other value (including things like `"A,B"` or
   `"E"`) is rejected.
5. Each option must fit within its printed column (~16 characters at the default
   template's font/column width, measured against the actual PDF layout in
   `app/config/pdf_template.json` — not a fixed character count). An option that's too
   long to print without overlapping the next option's bubble is rejected with a
   message telling the professor roughly how many characters fit.

A row that fails multiple rules gets all of its failure reasons reported together, not
just the first one that trips.

## Example

| question_text                             | option_a  | option_b   | option_c    | option_d  | correct_option |
|---------------------------------------------|-----------|------------|-------------|-----------|-----------------|
| What is the powerhouse of the cell?          | Nucleus   | Mitochondria | Ribosome  | Golgi apparatus | B         |
| Which molecule carries genetic information?  | ATP       | RNA polymerase | DNA     | Glucose   | C               |
| What process do plants use to make energy?   | Respiration | Fermentation | Photosynthesis | Osmosis | C          |

## Fixtures

Three `.xlsx` fixtures exercising this spec live under
`/backend/tests/fixtures/excel/`, generated by
`/backend/tests/fixtures/excel/generate_fixtures.py`:

- `valid.xlsx` — 3 well-formed rows, used to assert exact parsed field values.
- `missing_answer.xlsx` — one row with an empty `correct_option` cell.
- `duplicate_options.xlsx` — one row where `option_a` and `option_c` are identical text.
- `long_option.xlsx` — one row where `option_b` exceeds the printable column width.
